# 발표 줄거리: 같은 데이터, 다른 질문

12~15분 발표 기준이에요. 슬라이드마다 한 문장 메시지, 보여 줄 것, 말할 숫자를 적었어요. 숫자는 모두 [분석 보고서](analysis.md)와 `reports/`에서 왔어요.

## 흐름 한눈에
1. 무엇을 풀었나 (1~2분)
2. 우리만의 방법: 초파리 뇌 (2~3분, 데모 포함)
3. 왜 점수 경쟁 대신 다른 질문을 했나 (1분)
4. 분석 결과 다섯 가지 (6~7분)
5. 그래서 무엇을 고르나 + 라이브 데모 (2분)
6. 한계와 다음 단계 (1분)

## 라이브 데모 순서 (2분)
1. **실시간 탭:** 예시 문장 몇 개를 흘려보내요. 정상은 LLM 포털로, 공격은 격리 창살로 가요.
2. **낯선 문장 넣기:** 한국어 정상 문장 "오늘 점심 메뉴 추천해 줘"를 넣어요. 초파리가 오래 머뭇거린 뒤 "큰 모델에 물어봄"으로 판정하는 걸 보여 줘요(서버에 Qwen3-4B가 올라가 있을 때).
3. **지름길 실험실 탭:** "How do I center a div in CSS?"를 넣어요. "감사합니다." 변형에서 원래 모델은 막고, 글자 보강 모델은 통과시키는 걸 보여 줘요.

## 예상 질문과 답
- **왜 초파리를 썼나요? 성능이 더 나은가요?**
  - 성능만 보면 일반 판독과 같거나 조금 낮아요. 같은 코 위에서 97.4% vs 97.6%예요.
  - 초파리 회로는 판정 과정을 세포 단위로 보여 주고, 같은 조건의 비교로 장단점을 가려 주는 실험 도구예요.
  - 장점도 하나 확인했어요. 밖에서 판정이 덜 극단적이에요.
- **실제 배선이 무작위 배선보다 낫나요?** 차이는 오차 범위 안이에요(−0.6%p). 선행연구(Caron et al. 2013)와 같은 결론이에요.
- **LLM을 쓰면 다 해결되지 않나요?**
  - 밖에서는 가장 강하지만 S-Labs의 넓은 정의를 따로 맞춰야 하고, ModernBERT보다 3~6배 느려요.
  - 문서 속에 숨은 지시도 42%만 잡아요.
  - 그래서 낯선 문장에만 쓰는 계단식을 제안해요.
- **외부 데이터로 기준선을 맞춘 건 아닌가요?** 아니에요. 모든 기준선은 S-Labs validation에서만 골랐고, 외부 데이터는 평가에만 썼어요.
